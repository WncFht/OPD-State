# Agent Note: 训练基线与研究分层

Status: implemented

## 问题

OPD-State 的研究正文、精确实验和结果需要与可修改的 One-Shot-OPD 训练源码共同维护。上游 launcher 通过自身路径解析 vendored verl、数据和输出，直接拆散目录会增加迁移风险。原 README 是研究需求，缺少开发与复现入口。

## 决策

上游完整导入到 `training/one-shot-opd/`，使用普通 Git 文件跟踪，保留 LICENSE、NOTICE、README、文件模式和导入校验值。原研究材料归 `research/occupancy/`，过程与原始需求归 `notes/`，根 README 提供使用入口。架构与训练扩展位置归 [架构说明](../../../../docs/architecture.md)。

维护规则采用 agent-maintenance 的三个技能、完整共享引用、模板和 Notes 规则；检查集合归 `scripts/checks.json`，两阶段 hook、CI 与本地复用叶子检查。开发与 CPU 依赖独立锁定到根 `.venv`，不修改共享训练环境。原包的过程记录和可选 MPE 载荷未纳入。

根 formatter 跳过完整训练快照，避免格式变更覆盖算法差异。源码语法检查覆盖导入目录，日常模式允许算法修改；严格模式只验收原始导入。导入清单始终代表原始来源，不随实验改动重写。

## 考虑过的替代方案

submodule 需要另外提交训练修改，单个 OPD-State 提交无法完整描述实验代码与研究证据。把训练目录展开到根目录虽然少一层，但会混淆上游数据、图件与研究资产的归属。重写训练接口需要已有 GPU 基线；当前保留上游接口可以直接比较后续行为。

## 后果

一个提交可同时记录训练实现、实验配置和研究结论；后续同步上游需要审阅目录前缀下的差异。外部论文和绘图技能保持显式依赖，普通 CI 不要求安装绘图技能。

初始快照的 572 个文件校验一致，488 个 Python 文件与 5 个 Shell 脚本通过语法检查；五种 launcher 组合验证 vendored verl 路径和参数转发。迁移前后数学结果与 4,230 条曲线记录完全一致，真实部分暂存、违规暂存与失败传播测试通过。GPU 训练与 Hydra 实际配置尚未验收，上游与工作区共享环境的版本差异见[开发指南](../../../../docs/development.md#训练环境与验收)。
