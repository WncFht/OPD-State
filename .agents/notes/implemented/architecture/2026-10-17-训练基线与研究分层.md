# Agent Note: 训练源码根目录与文档归属

Status: implemented

## 问题

仓库用于直接修改 One-Shot-OPD 并运行研究实验。将源码放在 `training/one-shot-opd/` 会使仓库呈现为另一套项目包裹训练仓库；根目录分设 docs、notes、research 也增加了导航层次。这与用户要求的“在上游仓库上直接修改，只增加维护工具和研究文档”不符。

## 决策

One-Shot-OPD 的 recipe、data、eval、figs、verl、LICENSE、NOTICE 直接放在仓库根目录。根 README 作为 OPD-State 的算法、实现状态与运行入口，上游来源与许可归 `docs/provenance.md`；`verl/` 内部安装布局保持原样。根 `scripts/` 是本项目维护工具，原框架辅助脚本仍在 `verl/scripts/`。

项目资料统一归 docs：研究正文与可复现实验归 `docs/research/occupancy/`，过程和需求归 `docs/notes/`，来源与维护许可归 `docs/provenance/` 和 `docs/licenses/`。技能和长期决策继续保留在工具要求的 `.agents/`。

来源清单记录导入版本，日常检查只核验当前源码语法与相关行为，允许正常增删重构。代码修改位置见[代码结构](../../../../docs/architecture.md)，环境与检查见[开发指南](../../../../docs/development.md)。

## 考虑过的替代方案

上一版用嵌套目录保留上游相对路径，但把它的全部根目录内容一起上移也能保留同样的相对关系，因此嵌套层没有必要。根目录拆成三个资料区域有分类意义，但当前项目规模用 docs 内的子目录即可表达。继续拆开 `verl/` 的安装布局会改变原打包和导入协议，缺少当前需求。

## 后果

日常训练与代码修改直接使用上游原路径；文档导航集中在 docs。迁移需要同步 launcher 测试、正文外部引用、检查范围和数据忽略规则。root README 与 .gitignore 作为项目入口允许适配，训练算法源码按导入文件哈希核对保持一致。GPU 训练仍须建立独立环境并验收。
