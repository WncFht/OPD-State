# GitHub 推送与检查记录

## 目标与验收

将已有提交推送到 `WncFht/OPD-State` 的 `main`，保留正在进行的研究工作区改动。验证假设是本地推送门控可以检查实际提交，并与远端 CI 使用同一套维护检查。成功条件是有效提交通过、无效提交被拒绝、工作区与暂存区保持原状、远端分支与目标提交一致。若未提交内容能掩盖错误提交，或检查过程修改研究工作区，则否决现有 hooks 方案。CI 的运行镜像与发布方式仍可随项目需求调整；当前没有部署服务目标。

## 实现与取舍

保留已有两阶段 `pre-commit`，将 `pre-push` 改为读取 Git 推送协议，在临时 worktree 中检查每个不同的提交版本。原入口直接检查工作区，未提交的生成文件会阻断有效提交；新版复用本地维护依赖，检查完成或失败后移除临时目录。凭据检查覆盖待推送版本可达的提交历史，防止最新版本已删除的凭据被推送。只删除引用时没有待检查的提交。

安装器保留外来 hooks 和自定义 hooksPath，迁移时清理自己管理的旧 pre-push delegate。Python 依赖检查改为核对当前解释器中的 `pre_commit`，避免依赖 PATH 中其他环境的命令。Actions 从锁定依赖重建环境并执行 hooks 安装、完整维护检查和历史凭据扫描；增加手动触发与 15 分钟任务上限。使用说明归[开发指南](../development.md)。

目标仓库初始为空。SSH 使用工作区已有的配置，通过仓库本地 `core.sshCommand` 选择，不修改全局配置或复制密钥。保留 `upstream` 指向原始 One-Shot-OPD；`origin` 指向用户指定的 OPD-State。

## 验证证据

真实 Git 测试向独立 bare 仓库执行 push，覆盖工作区与暂存区均有非法内容时仍可推送有效提交、工作区修复无法掩盖非法提交、历史凭据删除后仍被拒绝、检查后的 worktree 清理、删除引用、多个引用的去重与外来 hook 保留。测试使用动态生成的合成凭据，输出保持脱敏。完整检查另覆盖训练源码语法、数学构造、文档、格式、维护集成测试与 launcher 参数转发。远端执行结果由 GitHub Actions 保存。
