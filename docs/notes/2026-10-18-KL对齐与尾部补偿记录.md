# KL 对齐与尾部补偿记录

用户要求以 KL 对齐为主要诊断，推导对齐和准确率的关系，并准备 JustRL-1.5B → R1-Distill-1.5B 与反方向的实验。用户明确选择无偏尾部补偿训练，同时记录合并尾桶 KL 和完整 KL 校准值。正式长时训练不在本轮启动。

MirrorOPD 的 `core/distributions.py::grouped_kl` 是粗粒化 KL，`tests/reference/test_kl_theory.py` 检查了完整尾部补偿的值与梯度恒等式；二者不是相同目标。生产 `topj_tail` 还是中心估计配置，不能照抄该名称便宣称训练完整 KL。

实施边界：新增严格的 fresh-student、单 batch 单更新、固定候选集合模式；保留全词表归一化，不将 head 重归一化。用冻结 score 系数实现无偏梯度，单独计算 KL 数值。先检查完整词表梯度、尾部支撑、mask/EOS/最后 action、全局 token 归约及来源拒绝条件，再运行四卡短 canary。仅使用 GPU 0–3。

研究正文新增条件与序列 KL 的链式关系、成功事件的 KL 分解、accuracy 差距上界，以及合并尾桶和无偏尾部估计的区别。推导同时说明 action 重要性修正不修正 prefix 测度，以及随机 token 数归一化的比率估计不能扩大解释为完整训练过程无偏。

真实运行发现 vLLM 和 learner 评分存在数值差异，尾项因此加入未裁剪的实际行为概率修正，并另记行为序列 log-ratio。HF checkpoint 校准又发现 Transformers 会从模型默认配置继承温度与 top-p；校准工具已显式关闭该行为，保留实际生成 scores 并拒绝有效词表内的非有限值。配方提高 epoch 上限，由步数预算终止，避免单 epoch 不足 300 步而提前停止。

8 项新增测试和全部 38 项相关产品测试通过。最终正向 1 步、反向 2 步四卡验证均成功，反向导出的 HF checkpoint 能重新加载校准。两个初始方向和该 checkpoint 共完成三次短完整词表校准。机器记录见[实现核验](../research/occupancy/results/alignment-implementation-check.json)；这些结果只用于工程验证，正式长训与泛化、收敛结论仍待后续实验。
