# Math 基线与 rollout 来源工作记录

## 目标与成功条件

验证本仓能在物理 GPU 0–3 完成 math sampled-token on-policy baseline 的 50 次更新，并仅在末步评测当前内存权重；不保存训练 checkpoint。W&B project 使用 OPD-State，在线指标与本地运行证据一致。随后形成三种 rollout 来源的实验文档，不在参数讨论前批量运行对照组。

成功条件是实际完成更新、参数有变化、梯度及 log-ratio 有限、末步评测有结果、没有中途 validation 或 checkpoint 文件。导入成功不能代替 GPU 训练通过。若训练只消费固定数据却被标记为 on-policy、W&B 未上传或更新次数与设定不符，则不算通过。

可变设置包括调试阶段的 batch、生成长度与验证规模；正式 50 步配置在独立配方中显式记录。论文复现实验的样本量、seed 与 cap 作为提案写入 docs/experiment。

## 核对

GPU 0–3 是空闲 H800 80GB，4–7 正由其他进程占用。已有 DeepSeek-R1-Distill-Qwen-1.5B、JustRL-DeepSeek-1.5B、DAPO train 与 MATH-500 val。原有 docs/research/AGENTS.md 删除是任务开始前的工作区状态，保留用户改动。

用户确认第三组是初始 student 一次性轨迹缓存（Semi-OPD），不是单条轨迹中 student→teacher 的切换。teacher 组对应论文的固定教师轨迹缓存。

现有 CUDA 12.6 环境可导入 trainer、teacher worker 和 actor worker；vLLM rollout 入口被 0.18 版本门槛拦截。相邻 MD-OPD 已有版本适配补丁，可作为复用起点；该补丁先前仅验证过 CPU 导入，仍需实际 GPU 核验。

## 调试记录

只读使用现有环境做了 CUDA 与两步链路诊断，没有安装或修改共享环境中的包。配置解析、数据筛选、四卡 NCCL、actor 模型初始化通过；生成服务被旧版 vLLM 不支持的 mm_processor_cache_gb 参数阻断。增加 AsyncEngineArgs 与 CompilationConfig 的接口能力检查，避免注入当前版本不存在的默认选项。

环境克隆包含约 49,180 个 pip 文件，网络文件系统串行复制速度过低。独立环境改放本地缓存 /root/.cache/opd-state/envs/train-cu126，工作区 envs/opd-state 为软链。复制复用 Conda 原 clone_env 的逐文件前缀替换与 explicit 包事务，仅将本任务进程中的文件复制循环并行化；源环境只读。失败的初始部分副本已在独立环境核验后清理，诊断日志继续保留在 runs/math-baseline。

独立环境已完成克隆，Torch 实际导入来自本地缓存副本，能看到且仅看到四张卡，CUDA 矩阵运算通过。Conda clone 重新引入了与 pip 覆盖层不同版本的 setuptools、packaging 元数据；仅在独立副本中重装为来源环境的 79.0.1、25.0，229 个包的依赖一致性检查通过。共享环境未安装或卸载包。

第四轮调试完成两步真实 GPU 更新与末步评测。loss 为 0.076824、0.083904，梯度范数 2.3353、2.5944，学习率 1e-6；第二步训练计时 20.52 秒，额外验证 2.28 秒。无中途 validation，无 checkpoint。新增五项生命周期单元测试验证旧版和新版 API 的调用、清缓存和失败传播；维护集成共十二项测试通过。
