# 三基准评测与轨迹来源实验

## 统一评测协议

所有新的 50 步对照，以及长时 Semi-OPD 每 50 步的验证，使用同一协议：AMC23 的 40 题、AIME25 的 30 题、MATH-500 的 500 题，每题采样 16 个 student 响应，共 9,120 个响应。采样 temperature 0.7、top-p 0.9，响应 cap 31,744，沿用 One-Shot-OPD 的验证设置。训练仍采用已验证的 batch 64、4K cap、temperature/top-p 为 1、学习率 $10^{-6}$。

`data.val_batch_size=32` 控制每次送入验证的题目数，不减少每题的 16 次采样。每批最多 512 个响应，避免将整个 9,120 条长响应一次性填充成大张量。完整验证必须通过三个基准题目数及每题响应数断言，缺少任何基准、重复 UID 数不对或非二值正确性均失败。结果保留 uid、data_source 和每条响应评分。

之前 [50 步 greedy 结果](2026-10-18-math50步基线结果.md)的 71% 仅作为工程链路检查，不参与本协议下的准确率对照。此前没有保存模型权重，在线学生组需重新训练并按新协议验证。

## 指标定义

某题共生成 $n=16$ 个响应，其中 $c$ 个正确。该题的 mean@16，即 avg@16，是 $c/16$。基准分数先对题内平均，再对该基准的题目平均，不把 16 次采样当成 16 个独立训练实验。

标准无放回 pass@k 的估计为

$$
\widehat{\operatorname{pass@k}}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}},\qquad k\in\{1,2,4,8,16\}.
$$

当 $n-c<k$ 时分子为零；当 $c=0$ 时结果为零。pass@1 等于 mean@16；pass@16 是该题 16 个响应中是否至少一个正确。实现用等价连乘避免大组合数，包含穷举计数对照测试。

上游 veRL 的 best@k 是有放回 bootstrap 统计，与上述 pass@k 不同。例如 16 个响应恰好一个正确，标准 pass@16 为 1，bootstrap best@16 的期望为 $1-(15/16)^{16}$。实现保留原生 mean/std/best/worst/maj 字段，并额外输出 `eval/<benchmark>/mean@16` 与 `pass@1/2/4/8/16`。

跨基准同时给出 macro 和 micro：macro 以三个基准等权平均；micro 以 570 个题目等权平均。二者名称分开，不能把 MATH-500 占主要权重的 micro 数值当成等权三基准成绩。上游 bootstrap 的向量化优化必须与参考算法逐项一致，包括多数投票的首次出现平局规则和 NumPy RNG 状态；单独保存优化前后微基准。

## 配对数据与固定轨迹

四种设置均只更新 student 参数，teacher 始终冻结。轨迹来源决定训练中使用哪些 prefix 和 action；student 在这些轨迹上重新计算自身 log-probability，接受原 teacher 的逐 token 监督。最终验证始终由更新后的 student 独立生成。

| 设置            | 训练轨迹生成方                                          | 生成时机               | 参数更新方 |
| --------------- | ------------------------------------------------------- | ---------------------- | ---------- |
| Student rollout | 当前 student                                            | 每次更新前在线生成     | student    |
| Teacher rollout | 固定 teacher                                            | 训练前一次性生成并缓存 | student    |
| Semi-OPD        | 初始 student                                            | 训练前一次性生成并缓存 | student    |
| Logit fusion    | 当前 student 与固定 teacher 在共享 prefix 上融合 logits | 每次更新前在线生成     | student    |

Teacher rollout 组使用固定 teacher 的预生成响应作为训练数据，teacher 同时提供监督，actor 为 student。每步重新采样 teacher 的变体尚未运行；重复使用有限缓存与持续采样新响应的差异需单独验证。

配对训练集采用原在线 baseline 的 RLHFDataset、StatefulDataLoader 和 seed 42，取前 50 个 batch，共 3,200 条消费记录。所有 50 个 batch 的 prompt 长度均值、最小值和最大值必须与原 baseline 日志一致；保存原过滤后索引、稳定样本身份、数据与 tokenizer 哈希。该集合用于三个 50 步对照，并在长 Semi-OPD 中重复消费；它不是论文的全量去重语料。

固定 teacher 和初始 student 分别预生成一次响应，只保存 token ID、EOS/长度结束标志和来源元数据，不保存模型 checkpoint。缓存以稳定 `opd_prompt_id` 与 prompt 内容哈希匹配，验证 SQLite 完整性和协议，cache miss 不允许调用当前模型补采样。

首版继续复用现有冻结教师的实时打分，当前学生 log-probability 每步重算。缓存不含 old_log_probs 或 PPO 锚点，不进行行为重要性修正。固定来源每步无需把学生权重送到生成端；只在验证前同步当前 student，验证后释放生成缓存。该设置改变轨迹来源及对应 action 分布，不能单独声称识别 prefix 测度的因果作用。

## 长时训练与融合

先完成三个匹配的 50 步结果，检查固定缓存 log-ratio RMS、梯度和跨 50 步评测轨迹。若仍有持续趋势，Semi-OPD 使用同一缓存延长，至少覆盖多轮重复训练，每 50 步在三个基准各采样 16 次。有限预算平台需要连续多个验证点与训练残差共同支持；仍下降或波动较大时继续增加预算并保留证据不足的结论。

Fusion 使用当前 student 与固定 teacher 在同一 prefix 的 logits，按 $(1-\lambda)z_S+\lambda z_T$ 融合，取 $\lambda=0.5$。两个模型接收完全相同的已采样 token，不能各自生成后拼接。教师监督仍来自原始 q；不把融合策略当成新的教师。实现、端点与缓存测试、GPU 基准和优化完成后，再按本协议训练 50 步并只用最终 student 验证。

三种来源和 fusion 的数学流程及控制项详见[原实验方案](2026-10-17-math基线与rollout来源对照.md)，其中的 greedy 阶段仅属于历史工程验收，当前运行与评测以本文为准。

## Fusion 实现与验收条件

`LogitFusionDecoder` 在每个 GPU 上维护两个独立推理副本。当前学生副本接收 actor 每次更新后的完整参数流，冻结教师副本始终保持初始权重。第 $t$ 步生成要求学生权重版本恰好为 $t-1$；参数流未结束、缺少参数或版本不符均拒绝生成。融合在相同的词表和同一 prefix 上执行：

$$
\mu_\lambda(a\mid s)=\operatorname{softmax}\!\left(\frac{(1-\lambda)z_S(s)+\lambda z_T(s)}{T}\right)_a.
$$

训练使用 $T=1$、top-p 为 1，不截断融合分布。每步只采样一个 token，再把同一个 token 送入两个模型各自的 KV cache。结束符属于有效响应；结束后的 padding 不计入训练 loss。融合策略的 log-probability 只作诊断，不作为 old-log-probability 或重要性权重。原 OPD 更新继续使用当前学生和原教师在该轨迹上的 token log-probability。

`dynamic` 后端提供动态 KV cache 参考实现；`static` 使用固定容量 KV cache；`cuda_graph` 在静态 KV 上捕获单 token 的双模型前向。`cuda_graph_flash` 使用 FlashAttention KV 接口，以物理缓存长度和左 padding 长度约束可访问的 key，保留分组查询注意力（GQA），避免将 KV 按 query head 复制。prefill 仍以 eager 模式执行。当前静态实现限 full-attention、相同 dtype，图捕获进一步限固定 default RoPE；FlashAttention KV 限 CUDA BF16/FP16。当前训练桥接限单 GPU 推理副本、单轮纯文本、每题一个 rollout、全参数 actor；不支持 LoRA 或 FP8 参数流。

以下是可复现的实现验收命令。CPU 测试已通过 12 项，覆盖几何分布、系数端点、同一 prefix、EOS、padding、缓存重置、冻结教师和参数版本。GPU 已验证 batch 1、8、16 的固定 prefix 对照、图与同内核 eager 的一致性，以及参数版本 0→1→2 的原地更新与恢复。独占 GPU 基准、完整两步训练及[正式 50 步实验](2026-10-18-logit融合50步结果.md)均已完成。

    ../envs/opd-state/bin/python -m unittest discover -s verl/tests/opd -v
CUDA_VISIBLE_DEVICES=0 PYTHONPATH="$PWD/verl" \
    ../envs/opd-state/bin/python data/prep/benchmark_logit_fusion.py \
    --student "$PWD/../models/DeepSeek-R1-Distill-Qwen-1.5B" \

GPU 基准在固定 prefix 上比较动态参考、静态 eager 和 CUDA Graph 的 logits 与概率分布，并记录 batch 1、8、16 的生成吞吐、首次调用开销和峰值分配显存。后端取舍以实测结果为准，不能仅凭成功捕获图判断优化有效。[真实两步训练证据](results/2026-10-18-fusion-two-step-smoke.json)包含每步学生版本 0→1、lambda 0.5、有限梯度与行为 log-probability，以及最终 student-only 短验证。该调试使用 batch 8、训练响应 cap 64、验证 cap 128，六题各 16 个响应共 96 条，退出码为 0；它验证训练集成，不作为任务准确率结论。图路径正式 50 步仍使用共同的 4K 训练与完整 eval16 协议。

数值验收区分同内核图捕获与跨内核精度。相同 FlashAttention KV 内核的 eager/graph logits 最大差值须小于 $10^{-5}$，现有三种 batch 实测均为零。原 SDPA 静态/动态 FP32 对照的最大 logits 差为 $4.96\times10^{-5}$，最大分布总变差为 $2.27\times10^{-6}$。FlashAttention KV 另以含左 padding 的多种原始 Q/K/V 张量直接对照 FP32 SDPA 数学内核，要求相对 L2 误差小于 0.005，现有实测为 0.00159–0.00199。该检查覆盖完整 prefill、单 token decode 和 GQA。

跨 BF16 attention 内核的多层模型存在舍入累积：现有 batch 1、8、16 的最大分布总变差约为 0.029–0.031，最大 logits 差不超过 0.375。最初 0.01 的总变差阈值不能覆盖这种精度差异；在完成 FP32 mask 对照与逐 attention 的独立验证后，跨内核 BF16 阈值设为总变差 0.05、logits 差 0.5，同内核 graph/eager 阈值保持 $10^{-5}$。这些条件属于当前模型的数值验收，不代表不同内核采样会逐 token 相同。共享 GPU 下的耗时只作诊断；正式性能报告必须核对 `timing_isolated=true`。

## 顺序运行与长时预算

`recipe/run_math_sources.py` 将实验串行安排到前四张 GPU：等待指定 teacher 进程退出并核对成功标志，独立重算 teacher 指标，等待显存释放，运行独占 GPU 基准和 Fusion 两步调试，然后生成初始 student 缓存，运行 Semi-OPD 50 步、在线 student 50 步、通过调试后的 Fusion 50 步，以及 Semi-OPD 长时训练。Fusion 调试失败时保留失败日志并继续两个独立的来源实验，不把失败的 Fusion 当成结果。

脚本固定训练源码和独立工具的提交，并核对 recipe 文件仍与该提交相同。每阶段保存命令、退出码和日志位置；状态文件只表示调度状态，实验完成以子进程成功退出及结果采集断言为准。各组均从相同初始模型重新开始，保存指标和响应，不保存模型 checkpoint。

长时运行的最大预算现设为 800 步，从 300 步起使用下述预先固定的经验平台判据。未达到判据时保留同一训练进程，继续每 50 步验证；达到判据时在该次验证结束后正常退出，保存停止原因和实际训练步数。达到 800 步仍未满足时记录 `budget_exhausted=true`，结论仍是平台证据不足，需要再决定后续预算。该机制避免在 300 步退出、又因未保存权重而重新训练。

以下参数使用现场确认的 teacher pipeline PID、运行目录与成功日志。不要复用历史 PID；进程启动时间也参与等待判断，避免 PID 被其他进程复用。失败阶段需先检查对应日志，再以新 suite 目录启动所需实验；脚本不覆盖已有缓存，也不会停止其他 Ray 作业。

```bash
python3 recipe/run_math_sources.py \
    --revision HEAD --directory runs/rollout-sources/实际调度目录 \
    --wait-pid 实际PID --teacher-run runs/rollout-sources/实际teacher运行目录 \
    --teacher-status-log runs/rollout-sources/teacher-pipeline.log --long-steps 800
```

## 配对比较与经验平台判据

逐题表新增由基准名、格式化输入和标准答案共同计算的 `question_sha256`，不使用每次运行随机生成的 validation UID 配对不同实验。同题的 16 个响应必须具有相同内容身份。采集器保存逐题 CSV 哈希及自身源码哈希；分析器校验题目集合、正确次数、逐题指标和基准聚合值。旧采集器产物可从具有已记录 SHA-256 的原始响应恢复题目身份。

`eval/analyze_math_sources.py` 输出每组每基准及 macro/micro 的 mean@16 和 pass@k，并以在线学生为参考计算配对 mean@16 差值。95% 区间采用分基准、成对重采样题目的 bootstrap，默认 5,000 次、seed 42。该区间表示结果对题目选择的敏感性，不估计训练随机种子之间的方差。单个训练 seed 的比较不能证明某个算法普遍更好。

```bash
.venv/bin/python eval/analyze_math_sources.py \
    --result teacher=teacher结果目录 --result semi-opd=semi结果目录 \
    --result student-online=online结果目录 --reference student-online \
    --output 结果比较目录 --step 50
```

经验平台至少需要 300 步和最后连续四个、间隔 50 步的完整验证点。四点 macro mean@16 的极差须不超过 0.01，即一个百分点；对应四个 50 步窗口的 token 加权 log-ratio RMS 相对极差须不超过 5%，平均梯度范数的相对极差须不超过 10%。相对极差定义为“最大值减最小值，再除以均值”；均值为零时使用 $10^{-12}$ 作分母下限。该阈值是提前固定的工程停止条件，不是统计显著性检验，也不意味着梯度为零或已与教师对齐。

第 $b$ 个 batch 的有效响应 token 数为 $N_b$、记录的 RMS 为 $r_b$。一个窗口的合并残差为

$$
r_{\mathrm{window}}=\sqrt{\frac{\sum_b N_b r_b^2}{\sum_b N_b}}.
$$

当前所有训练 batch 均为 64，使用 batch 平均响应长度作权重与使用 $N_b$ 等价。梯度范数在 50 次更新间取平均。训练器与事后分析器共用判据函数，分别从实际训练指标和归档 CSV 构造窗口。在线停止仅允许固定缓存、恒定学习率且无 warmup、完整三基准 eval16 每 50 步验证、不保存权重和不恢复训练的设置；其余设置拒绝启用该功能。低于观察预算记录 `insufficient_observation`，满足条件记录 `observed_plateau`，其余记录 `criterion_not_met`。准确率保持不变、训练残差仍下降时，判据不会通过。

调度器在三组 50 步对照完成后立即生成比较，Fusion 完成后追加第四组；长时组完成后再追加平台判断。所有阶段保留各自的原始证据，结果仍需结合训练残差的绝对大小、剩余趋势和训练 seed 数量解读。
