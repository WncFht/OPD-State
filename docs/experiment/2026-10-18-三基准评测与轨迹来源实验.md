# 三基准评测与轨迹来源实验

## 统一评测协议

所有新的 50 步对照，以及长时 Semi-OPD 每 50 步的验证，使用同一协议：AMC23 的 40 题、AIME25 的 30 题、MATH-500 的 500 题，每题采样 16 个 student 响应，共 9,120 个响应。采样 temperature 0.7、top-p 0.9，响应 cap 31,744，沿用 One-Shot-OPD 的验证设置。训练仍采用已验证的 batch 64、4K cap、temperature/top-p 为 1、学习率 $10^{-6}$。

`data.val_batch_size=32` 控制每次送入验证的题目数，不减少每题的 16 次采样。每批最多 512 个响应，避免将整个 9,120 条长响应一次性填充成大张量。完整验证必须通过三个基准题目数及每题响应数断言，缺少任何基准、重复 UID 数不对或非二值正确性均失败。结果保留 uid、data_source 和每条响应评分。

之前 [50 步 greedy 结果](2026-10-18-math50步基线结果.md)的 71% 仅作为工程链路检查，不参与本协议下的准确率对照。此前没有保存模型权重，在线学生组需重新训练并按新协议验证。

## 指标定义

某题共生成 $n=16$ 个响应，其中 $c$ 个正确。该题的 mean@16，即 avg@16，是 $c/16$。基准分数先对题内平均，再对该基准的题目平均，不把 16 次采样当成 16 个独立训练实验。

标准无放回 pass@k 的估计为

$$
\widehat{\operatorname{pass@k}}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}},\qquad k\in\{1,2,4,8,16\}.
$$

当 $n-c<k$ 时分子为零；当 $c=0$ 时结果为零。pass@1 等于 mean@16；pass@16 是该题 16 个响应中是否至少一个正确。实现用等价连乘避免大组合数，包含穷举计数对照测试。

上游 veRL 的 best@k 是有放回 bootstrap 统计，与上述 pass@k 不同。例如 16 个响应恰好一个正确，标准 pass@16 为 1，bootstrap best@16 的期望为 $1-(15/16)^{16}$。实现保留原生 mean/std/best/worst/maj 字段，并额外输出 `eval/<benchmark>/mean@16` 与 `pass@1/2/4/8/16`。

跨基准同时给出 macro 和 micro：macro 以三个基准等权平均；micro 以 570 个题目等权平均。二者名称分开，不能把 MATH-500 占主要权重的 micro 数值当成等权三基准成绩。上游 bootstrap 的向量化优化必须与参考算法逐项一致，包括多数投票的首次出现平局规则和 NumPy RNG 状态；单独保存优化前后微基准。

## 配对数据与固定轨迹

配对训练集采用原在线 baseline 的 RLHFDataset、StatefulDataLoader 和 seed 42，取前 50 个 batch，共 3,200 条消费记录。所有 50 个 batch 的 prompt 长度均值、最小值和最大值必须与原 baseline 日志一致；保存原过滤后索引、稳定样本身份、数据与 tokenizer 哈希。该集合用于三个 50 步对照，并在长 Semi-OPD 中重复消费；它不是论文的全量去重语料。

固定 teacher 和初始 student 分别预生成一次响应，只保存 token ID、EOS/长度结束标志和来源元数据，不保存模型 checkpoint。缓存以稳定 `opd_prompt_id` 与 prompt 内容哈希匹配，验证 SQLite 完整性和协议，cache miss 不允许调用当前模型补采样。

首版继续复用现有冻结教师的实时打分，当前学生 log-probability 每步重算。缓存不含 old_log_probs 或 PPO 锚点，不进行行为重要性修正。固定来源每步无需把学生权重送到生成端；只在验证前同步当前 student，验证后释放生成缓存。该设置改变轨迹来源及对应 action 分布，不能单独声称识别 prefix 测度的因果作用。

运行入口：

```bash
bash recipe/math_baseline.sh
bash recipe/math_cached.sh cached_teacher runs/rollout-sources/teacher-cache
bash recipe/math_cached.sh cached_initial_student runs/rollout-sources/student-cache
```

`math_baseline.sh` 默认执行新的三基准 16-sample 协议，50 步末次验证；`math_cached.sh` 用相同评测，并在延长时每 50 步验证。源代码、缓存与运行配置分别记录提交和哈希，不能从一个历史文件名推断使用了哪种评测。

## 长时训练与融合

先完成三个匹配的 50 步结果，检查固定缓存 log-ratio RMS、梯度和跨 50 步评测轨迹。若仍有持续趋势，Semi-OPD 使用同一缓存延长，至少覆盖多轮重复训练，每 50 步在三个基准各采样 16 次。有限预算平台需要连续多个验证点与训练残差共同支持；仍下降或波动较大时继续增加预算并保留证据不足的结论。

Fusion 使用当前 student 与固定 teacher 在同一 prefix 的 logits，按 $(1-\lambda)z_S+\lambda z_T$ 融合，取 $\lambda=0.5$。两个模型接收完全相同的已采样 token，不能各自生成后拼接。教师监督仍来自原始 q；不把融合策略当成新的教师。实现、端点与缓存测试、GPU 基准和优化完成后，再按本协议训练 50 步并只用最终 student 验证。

三种来源和 fusion 的数学流程及控制项详见[原实验方案](2026-10-17-math基线与rollout来源对照.md)，其中的 greedy 阶段仅属于历史工程验收，当前运行与评测以本文为准。
