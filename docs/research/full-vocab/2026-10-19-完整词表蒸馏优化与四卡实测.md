核验日期：2026-10-19。对象是 OPD-State 当前的 DeepSeek-R1-Distill-Qwen-1.5B student 与 JustRL-DeepSeek-1.5B teacher，以及固定 rollout prefix 上的完整条件 reverse KL。原生训练入口和算法尚未修改；本文交付独立研究原型、真实模型短更新、源码审计与容量外推。

**四张 H800 80GB 足以进行当前模型对的完整词表训练。**独立原型使用完整模型副本、FP32 student 参数与 Adam 状态、BF16 计算、FlashAttention2、逐层激活重计算和 token 分块输出头。在四卡 global batch64、总长度 4096 下，每次更新约 5.65 秒，单卡最大 allocated42.78GiB；总长度 8192 下约 10.87 秒、43.55GiB。时间包含 teacher 前向、student 前反向、DDP 同步和 optimizer，不含 rollout、Ray、权重发布与评测。完整 verl 集成尚待验收。

## 显存与速度分别由什么决定

### 显存取决于同一时刻哪些张量仍然存活

每卡峰值可以按以下对象记账，各项取同一时刻 t 的实际驻留量：

$$
M_{\rm peak}=\max_t\left[M_{\rm parameters}(t)+M_{\rm gradients/optimizer}(t)+M_{\rm activations}(t)+M_{\rm teacher\ cache}(t)+M_{\rm head/KL}(t)+M_{\rm communication/runtime}(t)+M_{\rm rollout}(t)\right].
$$

不能把 teacher 评分阶段、student 训练阶段和 rollout 阶段各自的峰值机械相加。分阶段运行只有在前一阶段的显存确实释放或 offload 后才节省峰值；vLLM 已暂停生成但仍保留 KV 池时，训练仍需支付这部分驻留量。

student 与 teacher 在这里明显不对称。student 需要参数梯度、optimizer 状态以及用于 backward 的激活；teacher 没有这些训练状态。teacher 可以只留下最终 hidden 和冻结 head。student 最终 hidden 即使体积很小，也不能单凭缓存它就替代训练计算图；要训练 backbone，仍须保留必要激活，或在 backward 重计算。

full-vocab 额外显存的主要风险是词表方向的 N×V 张量：双方 logits、log-prob、概率和反向中间量可能同时存在。token 分块 C 把这部分工作区限制在 C×V 的量级；teacher hidden 缓存把跨阶段表示从 N×V 改成 N×H。两者分别处理临时工作区与长期缓存，不能相互替代，也不会消除 student 参数/optimizer 的固定成本。若 teacher 完整模型常驻，head 已经包含在其权重内，不应再次重复计入模型权重；只卸载 teacher backbone 时才单独列出保留的 head。

### 速度取决于执行的计算、搬运和同步

在串行阶段调度下，整步时间可写成

$$
T_{\rm step}=T_{\rm rollout}+T_{\rm teacher}+T_{\rm student\ forward/backward}+T_{\rm head/KL}+T_{\rm optimizer}+T_{\rm transfer/sync/refit}.
$$

这里 student 与 teacher 项中的 backbone 计算同 head/KL 分开记账；若计时器把 head 放在模型 forward 内部，则不能再重复加一次。异步执行时看关键路径，不能把已重叠时间继续相加。冻结 teacher 只省去它的 backward 和 optimizer，仍然需要前向计算目标分布。

常规完整输出头下，双方 hidden 到 logits 的投影成本为 $2NV(H_s+H_t)$ FLOPs；若 student head 和 hidden 均需梯度，其线性层 backward 另约 $4NVH_s$。这里一次乘加按 2 FLOPs 计，未计 softmax、KL、backbone 和重算。sampled/top-k 在本仓的完整归一化输出头路径中同样支付词表投影成本。只取少数 token 作为 loss 项，不能直接把 GEMM 成本缩成 K/V。

token 分块主要缩短张量存活范围，并不减少总投影元素数。小块可能增加 kernel 启动、反复权重读取和 GEMM 效率损失。另一方面，减少中间量、融合归约或避免显存溢出可提高实际吞吐；哪一项占主导需要测量。此次 4K 对照是显存降低 20.7%、时间增加 4.3%，因此应称为容量收益，不称为分块加速。

teacher hidden 缓存也有两种不同成本。若一开始只跑 teacher backbone、尚未执行 head，训练阶段投影 head 是原本就需要的计算，未额外重算一次 head；若已有 teacher logits 又丢弃，后续才重新投影，则增加了 head 计算。多次 student 更新复用同一 teacher hidden 可省 teacher backbone 重复前向，但相对缓存完整 q，需要每次重建 teacher 分布。具体选择取决于缓存空间、通信带宽和更新次数。

| 优化动作                    | 对显存的主要影响                 | 对速度的主要影响                                   | 当前判断                                                   |
| --------------------------- | -------------------------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| teacher 完整分布改存 hidden | 跨阶段缓存 O(NV) 降为 O(NH)      | 少搬运大张量；需在消费端投影 head                  | 优先采用，当前模型每 token 表示相差约 99 倍宽度            |
| token 分块 512/1024         | 限制同时驻留的词表工作区         | 总 GEMM 量基本不变，分块和归约可有额外成本         | 512 容量更好，1024 输出头局部更快                          |
| 词表再次分块                | 工作区进一步到 O(CK)             | 增加循环、归一化统计与可能的重投影                 | 先在更长序列/更大模型上按需求启用                          |
| student 激活重计算          | 少保存 backbone 中间激活         | backward 增加前向重算                              | 长序列容量收益明显，不是免费提速                           |
| 取消独立 student 无梯度评分 | 少一次评分临时量；不消除训练状态 | 省一次 student 逻辑前向                            | 直接 KL 不依赖 old log-prob；融合的 sampled/top-k 也可实现 |
| teacher 常驻                | 增加常驻权重占用                 | 避免反复 CPU/GPU 搬运                              | 当前 teacher 仅约 3.31GiB，原型选择常驻                    |
| teacher/optimizer offload   | 降低相应阶段 GPU 占用            | 增加搬运，只有实际重叠时才隐藏延迟                 | 容量不足时采用，不默认更快                                 |
| DDP 从 4 卡增至 8 卡        | 每卡副本状态基本不变             | 固定 global batch 下每卡处理条数减半，增加同步范围 | 主要提升吞吐；八卡速度尚未实测                             |
| FSDP/ZeRO分片               | 减少每卡模型/梯度/optimizer 驻留 | 引入参数收集与梯度通信                             | 更大模型的容量手段，收益依赖通信布局                       |

### rollout 来源如何影响这些成本

同一批固定 token、相同长度与归约下，蒸馏评分和更新不需要按来源更换 student：当前 student、初始 student、teacher、fusion 或分段来源均使用当前 student 带梯度前向和冻结 teacher 前向。来源主要先影响生成成本：fusion 需要两个模型参与生成，分段可能增加重新 prefill，batch 混合可能产生负载不均；这些应单独计入 rollout 阶段。

自然生成的长度、EOS 比例和前缀分布也随来源改变，继而改变评分 token 数、attention 计算和各 rank 的等待。即使条件 loss 完全一致，总耗时也不必相同。对算法执行效率作因果比较应复用同一组真实轨迹；对完整来源策略比较则报告实际 token 数、分阶段时间和质量，不能把长度缩短全部归因于 KL 实现更快。

## 保持目标不变的优化

### 缓存 teacher 最终 hidden，按需重建分布

记有效 response 预测位置数为 N、teacher hidden 宽度为 H、共同有效词表为 V。完整 teacher log-prob 缓存是 O(NV)，最终 hidden 缓存是 O(NH)，另有共享 head O(VH)。必须保存最终归一化后、实际送入 head 的 hidden，并绑定 head 版本、bias、温度、tokenizer 和有效词表范围。

本机 H=1536、有效 V=151665、物理输出行数 151936；两模型均为 1777088000 个参数，未绑输入/输出 embedding。BF16 teacher 全部权重约 3.31GiB，输出 head 约 0.435GiB。BF16 hidden 比 BF16 logits 的宽度小约 98.74 倍；相对 FP32 log-prob，每 token 字节小约 197.48 倍。

| 全局 batch64 的缓存上界         | response4096 | response8192 |
| ------------------------------- | -----------: | -----------: |
| 一份完整 teacher log-prob，FP32 |    148.11GiB |    296.22GiB |
| 一份 teacher hidden，BF16       |      0.75GiB |      1.50GiB |
| 四 rank 平均分摊 hidden         |    0.1875GiB |     0.375GiB |
| 八 rank 平均分摊 hidden         |   0.09375GiB |    0.1875GiB |

上表是 response 达到上限时的缓存，不是训练峰值；训练实验的 4K/8K 指 prompt 加 response 的总长度。单教师 1.5B 可以先常驻，省掉频繁 offload。需要保留现有分阶段 worker 时，可让 teacher worker 输出 hidden，由 actor 持有冻结 head 并重建；无需把完整分布通过 Ray 搬运。多教师才进一步引入按 teacher 分组、双缓冲与异步预取。

### 分块完整词表及反向

在固定 prefix 上，令 p 为 student、q 为 teacher，e=log p−log q，D=Σp e。对 student logits z 有

$$
\frac{\partial D}{\partial z_a}
=p_a\left(e_a-\sum_b p_b e_b\right)
=p_a(e_a-D).
$$

因此可以在 token 块中计算完整词表归一化与 D，取得该块 hidden/head 梯度后释放词表临时量。prototype 在自定义 autograd forward 中调用块内 autograd，累计 head 梯度，在外部 backward 时把 hidden 梯度送回 backbone。这是仅支持一阶梯度的研究实现，不是新目标。

只在 Python 中循环计算各块 loss、最后统一 backward，仍可能保存全部块的反向中间量。真正有界实现需要块内取得梯度，或在 backward 重投影。输出 head 参数梯度 V×H 本身不会因分块消失。

更长序列或更大词表可增加词表块 K，使用在线最大值、指数和与加权矩归约：

$$
D=\frac{\sum_a e^{z_{p,a}}(z_{p,a}-z_{q,a})}{Z_p}-\log Z_p+\log Z_q.
$$

实际实现须用共同最大值重标定避免溢出，并跨全部词表累积。token/词表双分块把投影工作区限制到 O(CK)，代价是多次 GEMM 与可能的反向重算。当前 4K/8K、1.5B 先用 token512/1024 分块即可，不必优先把词表块缩到 4096。

### 精度、缓存与减少额外前向

概率、log-sum-exp、KL 与归约使用 FP32，teacher 停止梯度，student 保留完整 KL 梯度。FP32 参数与 Adam 状态保持在训练端。BF16 输出头乘法可保留，但分块形状会改变矩阵乘法和梯度归约舍入，必须对照数值。

此次发现两项实质问题。其一，块内反复创建 detached head 叶子会被外层 autocast 缓存成多份 BF16 head；关闭块内 autocast cache 后，128-token 块峰值从 17.49 降到 3.59GiB。其二，允许 BF16 低精度归约时，小 M 形状产生较大误差；关闭`torch.backends.cuda.matmul.allow_bf16_reduced_precision_reduction`后明显改善。两者分别影响存储生命周期与数值，不应混为一个“kernel 优化”。

纯 full-vocab KL 不依赖 old log-prob 或 PPO advantage，可以移除独立 student 无梯度评分，直接 teacher 前向＋student 训练前向。原型已采用这一结构；现有 verl trainer 仍保留旧链路。sampled/top-k 若在同一 microbatch 内由当前 student logits 构造停止梯度系数，也可只保留一次 student 带梯度前向，因此这一收益来自执行布局，不应全部归因于 full-vocab。用于日志的 entropy 和 KL 可随训练头归约取得，避免因诊断再做完整模型前向。

### 并行策略

当前 1.5B 配对在完整副本 DDP 下已能运行，四卡/八卡优先增加数据并行，不必为词表求和先上 TP。正式接入保留已有 FSDP 后端，不要求为原型切换框架。rollout 与训练分阶段执行，训练时必须释放或休眠 vLLM 的 KV 和相关显存池。

对 7B 及以上，可用 FSDP/ZeRO 分片训练状态；长序列再评估 CP。若采用词表 TP，正确的无完整 logits 收集方法是：各 rank 计算本地 logits，跨 rank 归约每 prefix 最大值与指数和，计算本地 KL 贡献，再归约 KL 标量；反向在本地计算 p(e−D)，hidden 梯度按并行合同归约。将 V 维 logits 先 all-gather 到每卡会抵消词表分片的显存收益。

## GPU 实验

### 条件与计量

独立环境为 Torch2.7.1+cu126、Transformers4.57.6，物理 H8000–3。真实输入来自既有 validation token 文件，选择达到目标总长度的前若干条，再截到 4096/8192；不生成新轨迹，不评价数学准确率，不保存更新后的 checkpoint。prompt 不计 loss，response 从前一预测位置对齐，共同合法词表 151665 全部参与。

student 参数、梯度和 Adam 状态为 FP32，计算 autocast BF16；teacher BF16 无梯度；启用 FlashAttention2 和逐层非重入激活重计算。每卡 microbatch1，四卡 batch64 需要每 rank 累计 16 条，前 15 条 DDP no_sync，最后一次同步。按全局有效 response token 加权，避免不同 prompt 长度导致 rank 权重不同。学习率 1e-6、weight decay0、梯度裁剪 1。

每种配置在独立进程启动，训练 3 个 step；step0 预热并创建 optimizer 状态，报告 step1/2 的最慢 rank 耗时中位数，显存取全部 step/rank 最大值。没有多 seed 或长训练稳定性证据。allocated 是 PyTorch 活跃分配峰值，reserved 是 allocator 保留峰值，均不包含所有 CUDA/NCCL 运行时显存；不能把它们直接叫整卡峰值。

### 输出头配对测量

固定同一条真实 4K 输入及双方 hidden/head，完整词表，测一次预热加三次前反向。下表使用关闭 BF16 低精度归约后的配置：

| 执行方式     | 前反向中位/ms | allocated/GiB | reserved/GiB | hidden 梯度相对 L2 误差 | head 梯度相对 L2 误差 |
| ------------ | ------------: | ------------: | -----------: | ----------------------: | --------------------: |
| 完整矩阵参照 |         99.22 |         15.34 |        16.49 |                       0 |                     0 |
| token128     |        175.55 |          3.59 |         4.54 |                 0.0362% |               0.1932% |
| token512     |        111.43 |          4.46 |         5.96 |                 0.0283% |               0.1914% |
| token1024    |        102.53 |          6.20 |         7.40 |                 0.0282% |               0.2102% |

最大 loss 绝对误差 1.49×10⁻⁸。FP64 小形状检查的 loss/梯度误差低于 1e-12，并核验 teacher 无梯度、非单位上游缩放。真实 BF16 梯度并非逐位相同；1% 相对 L2 仅作为这个局部试验的工程筛查线，不代表长期训练效果等价。

默认允许 BF16 低精度归约时，token128 的 hidden 梯度相对误差约 7.52%，不采用该配置；token512 约 0.308%。关闭后，token128 误差降低但仍慢。token512 适合显存优先，token1024 适合有余量时争取吞吐。128 与 512/1024 的差异也说明不能仅靠“块越小，显存越省”决定生产配置。

前四行保留默认 BF16 归约开关，使用相同 FP32 概率语义；末行补测关闭低精度归约后的完整模型更新，其相对默认 8K 时间差约 0.47%，小于该短基准可据以判断稳定速度差的范围。4K 两种执行方式的输入 SHA256 完全一致。分块的 allocated 降低约 20.7%，reserved 降低约 27.7%，时间增加约 4.3%。这是省显存换少量时间的结果，不能表述为分块本身加速训练。

## 四卡到八卡的容量和速度

### 静态状态预算

按 FP32 student 权重 4 字节、梯度 4 字节、Adam 两份状态 8 字节，冻结 teacher BF16 为 2 字节：

$$
M_{\rm static} = 16P_s+2P_t,
\qquad
M_{\rm static,sharded}\approx\frac{16P_s+2P_t}{D}.
$$

后式假设双方状态均完全分片；不包含激活、活跃层 all-gather、head 工作区、通信、CUDA/NCCL 或 vLLM。表中 7B/32B 按标称参数量估算，未加载这些模型。

| student / teacher     | 完整副本静态/GiB | 四卡理想完全分片/GiB 每卡 | 八卡理想完全分片/GiB 每卡 |
| --------------------- | ---------------: | ------------------------: | ------------------------: |
| 当前 1.5B / 当前 1.5B |            29.79 |                      7.45 |                      3.72 |
| 当前 1.5B / 7B        |            39.52 |                      9.88 |                      4.94 |
| 7B / 7B               |           117.35 |                     29.34 |                     14.67 |
| 当前 1.5B / 32B       |            86.09 |                     21.52 |                     10.76 |

当前 DDP 原型实测 43–44GiB 活跃分配，比 29.79GiB 静态账目高，差额包含 DDP 桶、autocast 副本、backbone 与 head 临时量。四张 80GB 卡已足够；按每卡 55–60GiB 作初步运行预算可留出运行时与框架余量，但该预算不是已测的 verl 峰值。

八卡 DDP 仍会每卡复制模型和 optimizer，不会把 43GiB 自动减半；global batch64 时只是每 rank 累计由 16 条变 8 条。FSDP 才会减少静态分片。7B/7B 四卡在静态账目上有空间，八卡余量更大，仍须真实模型 canary 核验激活、通信和长序列边界。32B teacher 的算力与加载成本不能从 1.5B 结果线性承诺。

### 时间模型与端到端限制

以固定 global batch64、microbatch1 为条件，若四到八卡实现 1.5–2 倍训练阶段加速，则 4K 更新约 2.83–3.77 秒，8K 约 5.44–7.25 秒。区间是 75%–100% 理想扩展效率的情景计算，不是实测置信区间；八卡通信、同步和框架调度可能超出它。

原有四卡 student 来源 50 步实验中，step2–49 中位 rollout 生成 16.55 秒，旧 student 评分 1.92 秒，teacher 评分 1.96 秒，actor 更新 4.76 秒，权重发布 2.29 秒，整步 28.53 秒。这与新原型不是同一运行和同一数据，不能直接相除当作加速比。它说明即使消除一次 student 评分，rollout 仍然是重要成本；训练 kernel 加速不会等比例缩短端到端时间。

真实 4K 输出头配对约 0.11 秒/条，四卡每 rank16 条约 1.76 秒，与整次 5.65 秒相比占约 31% 的量级。即使输出头成本减半，按其他阶段固定的粗略模型，整次更新只减少约 0.88 秒。进一步优化应同时检查生成并发、权重发布、teacher hidden 传输和变长负载平衡。

## 对 OPD-State 的实施建议

1. 新增明确的 full-vocab 条件 KL 训练模式，rollout 来源只产生 prefix；teacher hidden 与冻结 head 成为监督输入。保留旧 sampled 路径作算法基线，避免把新目标混入现有来源结果。
2. 第一版保留现有 FSDP 与生成引擎，teacher 输出最终 hidden，actor 直接完整 KL 反向。token 块 512 起步，显存允许再测 1024；FP32 概率归约，关闭 BF16 低精度归约，禁止完整 batch 的词表张量经 Ray 传输。
3. 移除该模式的 old-log-prob 评分、PPO advantage 与 ratio，复用 KL 归约输出诊断。保证 prompt/response 预测位移、EOS、padding、合法词表、温度和全局 token 权重一致。
4. 当前模型可先保持 teacher 常驻；若并存 vLLM 或更大 teacher 造成压力，再使用 teacher 阶段缓存 hidden、卸载 backbone，只留 head。按显存测量决定 offload，避免无需要的 PCIe 搬运。
5. 正式接入先跑同轨迹数值/梯度对照，再做四卡短训练和来源切换；通过后才跑 50 步质量对照。八卡验证必须在空闲、获准的资源上单独执行。

不优先采用截断 SVD、低秩 hidden、teacher 量化或 top-k 丢尾：这些会改变分布或梯度，不属于此次“保持完整词表目标”的执行优化。也不为复用一个 KL 内核迁移整个 NeMo 或 DeepSeek 训练栈。

## 复现与产物

[独立基准脚本](experiments/benchmark_full_vocab.py)与[统计脚本](experiments/summarize.py)是新增研究代码；[summary.json](results/summary.json)包含每 rank 测量归约、显存公式、八卡情景、输入与结果哈希、上游 commit 及已读取文件哈希。早期结果先于脚本增加`source_sha256`字段，不能据最终脚本哈希追溯成字节级相同版本；其关键执行差异由文件名、参数及本报告保留。

关闭 BF16 低精度归约后的 head/四卡 8K 实验保存了实际执行的[源码快照](results/benchmark-source-cce7b5ba2490.py.gz)，解压后的 SHA256 为`cce7b5ba249052a3a50b6751e3159e107fb967a877a3b8074f50c30831b66d4b`。交付脚本随后只做了导入排序与格式整理；其哈希另列为`delivery_sources`，与测量源码区分。

从仓库根目录执行，运行前重新检查设备空闲：

```bash
CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=2 ../envs/opd-state/bin/python \
  docs/research/full-vocab/experiments/benchmark_full_vocab.py \
  --mode verify --output runs/full-vocab-reproduced/verify.json

CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=2 ../envs/opd-state/bin/python \
  docs/research/full-vocab/experiments/benchmark_full_vocab.py \
  --mode head --strict-bf16 --length 4096 \
  --output runs/full-vocab-reproduced/head.json

CUDA_VISIBLE_DEVICES=0,1,2,3 OMP_NUM_THREADS=2 NCCL_DEBUG=WARN \
  ../envs/opd-state/bin/python -m torch.distributed.run --standalone --nproc_per_node=4 \
  docs/research/full-vocab/experiments/benchmark_full_vocab.py \
  --mode train --strict-bf16 --length 8192 --accumulation 16 --steps 3 --chunk 512 \
  --output runs/full-vocab-reproduced/train.json
```

输入文件是本机既有真实 token 记录，未复制到 Git；脚本在长度不足时失败，不用随机 token 替代。复现默认归约对照时不传`--strict-bf16`；完整矩阵基线传`--loss dense --length 4096`。结果按 rank 独立写文件，命令不保存模型权重。
